# Build and verification contract

`Cargo.toml` is the version authority. The private root control package and public npm bindings
manifest mirror it; generation/build rejects version drift. Rust source owns the protocol.
`bun run protocol:generate` runs `examples/types.rs` with locked Cargo dependencies and formats its
output with pinned Biome. `bun run protocol:check` compares bytes and does not build Wasm or update
the file. `bun run build` additionally builds genuine release Wasm, uses wasm-bindgen-cli exactly
0.2.105 and emits ESM, declarations, relative maps and notices. `sideEffects: false` is retained;
explicit initialization calls must stay in consumer code.

Native requirements: Rust 1.94.0, wasm32-unknown-unknown, rustfmt and Clippy. JavaScript build tools:
Node 24 and Bun 1.4.2. Root `bun.lock` and `Cargo.lock` pin dependencies. Configurations are local;
there are no parent workspace aliases or external lint/TypeScript configurations. A recorded
patch fixes four unresolved references in Bun 1.4.2's development declarations for strict
TypeScript checking; no runtime dependency is patched. `skipLibCheck` remains false.

Use `node scripts/cargo.mjs ...` for release native commands. It pins the compiler, uses this
repository's `target/` and remaps source/dependency paths to portable compiler paths. The local
Cargo config also chooses `target/`. A raw Cargo invocation is useful in development but does not
supply the wrapper's absolute-path remapping. No command changes the global Rust default.
No environment file, backend, account or credential is required.

The local gates are the commands in README.md plus `bun run test:consumers`. Install the two
local browser builds first (Linux browser shared libraries must already be available):

```sh
PLAYWRIGHT_BROWSERS_PATH=.qualification/browsers node node_modules/@playwright/test/cli.js install chromium webkit
bun run test:consumers
```

The gate creates a fresh ignored project and logs each command and exit separately. It stops before
a subprocess when free disk falls below 10 GiB and uses the root Cargo target for native consumers.
Pass an optional receipt directory to `node scripts/verify-consumers.mjs /path/to/receipts` to retain
the JSON report elsewhere. The default is inside the ignored project.

The gate
packs and installs the actual tarball without workspace aliases, unpacks the actual crate, checks
positive and negative types and runs the same frozen stream, presence and list transcripts under
native Rust, Node, Bun, Chromium and WebKit. Window and asynchronous host tests run on installed
release bytes. The SQLite provider example runs under Bun's builtin SQLite. Test browser binaries
are local development inputs and are never shipped.

Generated output and temporary independent projects stay ignored. Verification receipts and
inventories are not package contents. The source crate includes its Rust tests, generator, lockfile
and legal notices. The JavaScript tarball includes only its manifest, README, generated glue/Wasm,
ESM/declarations/maps and legal/API contracts. The npm bindings are configured for public distribution; the root development package
remains private and the Rust crate keeps `publish = false`. Verification does not publish either artifact.

Compiler path remapping and relative maps prevent developer-directory strings in distribution
artifacts. Rebuilding with the same locked tools is checked for matching generated bytes; archive
metadata and platform/toolchain differences are not a cross-platform bit-for-bit guarantee.
Inspect archive contents and hashes before distribution. Local gates do not claim hosted CI,
remote publication, a security audit, universal performance or production approval.
